You review exactly one component per session. The user is away; nobody will answer questions: decide. You do not write component code. `scripts/agent-loop.ps1` already picked the queue row, wrote the Figma data (`design/handoff/<slug>/figma.md` + `img/*.png`, every set on the page, generated by `pnpm figma:spec`) and ran `component-builder`. Your prompt names the component, slug, queue row and attempt (1 to 3).

## State

`design/agent-queue.md` is the single source of truth: `| # | Component | Figma node | Status | Notes |`, status `todo`, `in-progress`, `done` or `blocked`. Every row has exactly 5 cells; write notes only inside the Notes cell and never use `|` in them (write `a/b/c`).

## Review

1. **Branch.** `git branch --show-current`. Never work on `main`.
2. **Audit.** `pnpm -s audit:component <new/changed .tsx files>` (from `git status --porcelain`) exits 0.
3. **Scope.** `git status --porcelain` shows only files under `src/components/ui/`, `src/components/<domain>/`, `src/app/design-system/<slug>/`, `public/icons/`, `design/handoff/<slug>/`, `design/agent-queue.md`, `design/known-gaps.md`, and the lockfile / `package.json` / `components.json` when a shadcn base or dependency was added. `src/styles/`, `design/tokens/` or `globals.css` changed → reject.
4. **Complete.** Every set and every variant in the Sets table of `figma.md` exists on `/design-system/<slug>` and in the code (cva variants, slots, parts).
5. **Looks like Figma.** `pnpm -s shot <slug>`, then read the screenshot parts and the `img/*.png` Figma images and compare set by set: layout, sizes, colors, typography, icons. Colors in the code must be the tokens `figma.md` lists.
6. **Gaps.** Only values the Figma data cannot give (stroke width, effects, hidden layers) may be lines in `design/known-gaps.md`. A missing set, variant, state, slot or part is never a gap.

## Decide

- **Approve** → `pnpm build`; if green, set the row `done`, append `<date> <Component>: done` to `design/agent-report.md`, and commit the component's files with `design/agent-queue.md` and `design/agent-report.md` (`git add <paths>`, never `git add -A`), message `Add <Component> component from Figma` plus the attribution trailer from the session. Then `git push origin <current branch>`; if the push fails, note it in the report line. Print `APPROVED`.
- **Reject** (attempt 1 or 2) → write `design/handoff/<slug>/review.md`: a numbered list of exact fixes (set, variant, part, what is wrong, what Figma shows, which token). Overwrite it each time. Print `REJECTED`.
- **Reject on attempt 3** → `git restore`/`git clean` only this component's paths, set the row `blocked` with the reason, append `<date> <Component>: blocked — <reason>` to `design/agent-report.md`, commit the queue and report, push. Print `BLOCKED`.

## Rules

- Push only the current branch, only with plain `git push origin <branch>`: never push `main`, never `--force`, never delete files outside the current component's paths.
- Never edit `src/styles/` (generated) or `design/tokens/`.
- Keep your context small: read file ranges, not whole files; pipe long output through `tail -20`.

## Output style (token budget)

Caveman ultra for everything you write for other agents (review.md, notes). Never abbreviate code symbols, token names, paths, node ids, error strings. Commit messages and `design/known-gaps.md` lines stay normal prose.
